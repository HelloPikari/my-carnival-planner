### Publish-status bug (found during verification)
- Every edition in every year was `draft`. Root cause: `load.ts` mapped only `"Confirmed"/"Active"` → `published`,
  but real Airtable statuses are `"Released" / "Not Announced Yet" / "Announced -- Not Released"`.
- Impact: `list_fetes` (trip path) filters `status='published'`, so it returned **nothing** for any season —
  including 2026. Never caught because admin testing uses `queryFetes` (master table, no status filter).
- Fix (Steve approved): map `"Released"` → `published`. After re-seed: 2025 = 55 / 2026 = 42 published,
  2027 = 0 (none released yet — correct).

### Production (additive, non-destructive)
- Wrote an idempotent, insert-only script (no drops): inserts 2027 season, inserts 107 2027 editions
  (idempotent by `airtableId`), and applies the publish-fix to existing editions (`airtableStatus='Released'`
  draft → published). Connects via raw `postgres-js` (drizzle's URL parsing chokes on the prod SSL params).
- Validated against local first: reset local to a prod-like state (delete 2027, all editions draft), ran the
  script, confirmed it reproduced the exact full-seed result, and confirmed idempotency (2nd run = 0 writes).
- Dry-ran then executed against prod. Result: 2025/2026/**2027** seasons; 2027 = 107 editions; 97 existing
  editions republished. **users (3) and trips (0) untouched** — no live data wiped.
