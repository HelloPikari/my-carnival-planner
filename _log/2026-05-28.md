### Root cause diagnosed and fixed: WorkOS multi-app JWT validation

**The bug:** Auth kept failing with issuer and audience validation errors. Two separate problems:

1. **Wrong `WORKOS_ISSUER`** — WorkOS pins the `iss` JWT claim to the *Default application's* `client_id` for the entire environment, not the specific app initiating auth. We had it set to My Carnival Planer's client_id (`client_01KSH7ESPNVZEPY7BDGPGY7N9S`). The actual `iss` in all tokens is `https://api.workos.com/user_management/client_01KREFHFZRYWAB2CSZED2773VD` (Pikari Todos MCP, which is the Default app).

2. **Wrong `audience` check** — WorkOS does not emit an `aud` claim in JWTs by default. Passing `audience: process.env.WORKOS_CLIENT_ID` to `jwtVerify` caused every token to fail because `aud` was absent.

**The fix:**
- Updated `WORKOS_ISSUER` and `WORKOS_JWKS_URI` in Vercel to use the Default app's client_id
- Removed the `audience` check from `jwtVerify` in `src/mcp/auth.ts`
- Added `client_id` claim check as the correct per-app isolation boundary (prevents tokens from Pikari Todos MCP being accepted on My Carnival Planer)
- Removed the incorrect `invalid_grant` rejection from `app/api/oauth/token/route.ts`

**Verified from live token:** `payload.iss = "https://api.workos.com/user_management/client_01KREFHFZRYWAB2CSZED2773VD"`, `aud = undefined`

### Reusable multi-app pattern documented

For any future WorkOS application in this account:
- `WORKOS_ISSUER` = `https://api.workos.com/user_management/client_01KREFHFZRYWAB2CSZED2773VD` (Default app — same for all apps)
- `WORKOS_JWKS_URI` = `https://api.workos.com/sso/jwks/client_01KREFHFZRYWAB2CSZED2773VD` (Default app — same for all apps)
- `WORKOS_CLIENT_ID` = this app's client_id (unique per app)
- Isolate per-app tokens via `payload.client_id` check in JWT validation

## Decisions made

- `client_id` JWT claim is the per-app isolation boundary in WorkOS multi-app environments — not `aud`, not a custom claim
- Default app's client_id is effectively shared infrastructure; don't change which app is Default without understanding the environment-wide impact on token issuance
